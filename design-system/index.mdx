The Invoca Design System documents reusable UI patterns, components, and content guidelines used across Invoca products. Use this section to learn how to adopt shared building blocks consistently and how to contribute new component documentation.

<Note>
  This product is **docs scaffolding** to help teams get started. It is not a complete component catalog or token library yet.
</Note>

## What you'll find here

- **Components** — documented UI building blocks with usage guidance, copy-paste examples, and props tables
- **Patterns** — common layouts and interaction models (coming soon)
- **Foundations** — color, typography, spacing, and accessibility guidance (coming soon)

## Get started

<Steps>
  <Step title="Browse the example component">
    Start with the [Button](/design-system/components/button) page to see the recommended structure for component docs: when to use it, a usage snippet, and a props/variants table.
  </Step>
  <Step title="Copy the page template">
    Duplicate the Button MDX file when documenting your next component. Keep the frontmatter (`title`, `description`) and section headings consistent so pages feel cohesive in search and navigation.
  </Step>
  <Step title="Wire it into navigation">
    Add your new page path under the **Components** tab in `docs.json` inside the `Invoca Design System` product block.
  </Step>
</Steps>

## Contributing

When you add or update design system docs:

1. Create MDX under `design-system/` (not under `en/latest/`, which is reserved for Developer Portal API docs).
2. Follow existing frontmatter and Mintlify component patterns from pages like [Basics](/en/latest/basics).
3. Mark work-in-progress pages clearly so readers know what is example scaffolding versus production-ready guidance.
