{/*
  PATTERN PAGE TEMPLATE

  A Pattern is a named composition of two or more components, with rules, that does
  NOT ship as an export. If it ships as an export it is a Component. If it defines
  full-page regions it is a View.

  A pattern page is problem-first. A component page can open with "what it is"
  because the reader arrived knowing the name. Nobody arrives at a pattern page
  knowing the name — they arrive with a problem. Keep that order.

  A pattern's value is in BEHAVIOUR and ORDER, not appearance. If this page has no
  sequence in it, what you are documenting is probably a component.

  Section order is fixed. Do not reorder, do not omit — a fixed order makes an
  omission visible.

  Three registers:
    [REF] code fact      — generated from source. Never hand-write a value.
    [DEC] design intent  — normative. What to build.
    [DIV] divergence     — where the two disagree. Links to /foundations/divergences.

  Delete these comment blocks when you author a real page.
*/}

<Note>
  **Everything on this page is design intent**, not generated — a pattern has no export and
  therefore no source to emit from. Constraints are **Proposed** until signed off. Values

  the design language and the shipped code are recorded in

</Note>

## Accessibility

{/* [DEC] Focus movement through the composition, what gets announced, and in what
     order.

     Individually accessible components compose into an inaccessible pattern more
     often than not — focus order is where it breaks. This is the tier that owns
     it; no single component can. */}

**Focus.** Where focus starts, where it moves on each step, and where it returns when the
pattern closes or completes.

**Announcement.** What assistive technology is told, when, and via which mechanism —
a live region, a focus move, or a role change.
