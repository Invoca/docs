  A View is a full-page archetype: it defines regions and what fills each one.

  This is the tier most design systems omit, and the tier a builder needs FIRST.

## Accessibility

{/* [DEC] The view tier owns the page-level accessibility decisions, and it is the
     only tier that can. A component cannot know it is the only `main`; a pattern
     cannot know the heading outline. If this section is thin, those decisions are
     being improvised per page. */}

**Landmarks.** Each region maps to a landmark role — see the Regions table. Exactly one
`main` per page. Repeated landmarks of the same role carry distinguishing accessible names.

**Heading outline.** One `h1`, and this page states which region owns it. Levels descend
without skipping. Visual size and heading level are chosen independently — never reorder
headings to get a size.

**Focus order.** Region order in the DOM matches visual order. State where focus lands on
load, and after any region-level navigation. Provide a skip link to `main` when the header
and navigation together exceed a few tab stops.

**Sticky regions must not obscure a focused element**
([WCAG 2.2 Focus Not Obscured, AA](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)).
A sticky header that covers the element a keyboard user just tabbed to is a conformance
failure, and this is the tier that can prevent it.

**Reflow.** Content works at 320px equivalent without two-dimensional scrolling
([WCAG 2.2 Reflow, AA](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)) — that is
a desktop page at 400% zoom, not a phone.

**A region dropped responsively must not be the only route to a function.** Dropping is a
layout decision; removing the only path to an action is a functional one.
